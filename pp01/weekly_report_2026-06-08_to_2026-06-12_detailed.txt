구현 세부사항

ALV Edit 유효성 및 UI 동작
- 허용 값 검증:
  - 수치 필드: 정수/소수 허용범위(예: 최소 0, 최대 논리적 상한) 검사.
  - 자재 코드: 존재 여부 확인(로컬 캐시 또는 Value Help 조회).
- UI 반응:
  - 유효성 실패 셀: 배경 색상 변경(경고 색), 셀 우측에 툴팁/아이콘으로 오류 메시지 표시.
  - SAVE 버튼: 모든 편집 셀이 유효한 경우에만 활성화.
  - 저장 중: 전역 로딩 인디케이터 표시, SAVE 버튼 비활성화.
- 오류 처리:
  - 서버 검증 오류(다음 단계): 각 행에 대한 서버 에러 메시지를 매핑하여 사용자에게 표시(예: 행#3: "재고 부족").

OrderDetail 계산 및 바인딩
- EA 단위: 소수점 표기 규칙 적용(정수 단위 또는 소수 3자리 등, i18n 포맷 적용 고려).
- 합계 수량: 바인딩된 리스트의 변경 이벤트(onChange)에서 실시간 재계산.
- 성능: 대량 데이터 처리 시 가상 스크롤 또는 페이징 적용 고려.

Value Help 개선
- 검색 성능: 키워드 인덱스(클라이언트 필터 우선) 적용, 결과를 50건 단위로 페이징.
- UX: 선택 후 원래 필드로 값 반영 및 포커스 복귀, 다중선택 시 카운트 표시.

테스트 및 문서
- 단위 테스트:
  - Main.controller의 입력/저장 핸들러에 대한 기본 유효성 테스트 추가.
- 통합(OPA) 테스트:
  - 네비게이션 경로 확인, OrderDetail 표시, Value Help 열기/선택 시나리오 자동화.
- 문서화:
  - i18n에 사용자 안내 메시지 키 추가(예: `MSG_SAVE_SUCCESS`, `MSG_SAVE_ERROR`, `MSG_VALIDATION_ERROR`).

버그 및 이슈
- 발견된 주요 이슈:
  - ALV 저장 불능: 유효성 플래그 초기화 누락으로 인해 SAVE가 비활성화되던 현상 — 해결 및 리그레션 확인 완료.
  - 화면 렌더링 오류: OrderDetail의 일부 필드가 null일 때 바인딩 처리 미비 — 방어 코드 추가로 수정.
